# Artek Brain: ТЗ (общий слой памяти и инструментов для людей и агентов)

## 0. Границы
Не агент, не харнесс, не LLM, не чат. Общий серверный слой памяти. Один экземпляр на команду/рой, много людей и агентов.
Ценность: проверяемая общая память. Память переживает смену модели, харнесса и вендора.

## 1. Принципы
1. Документ (Markdown + метаданные) — единица памяти.
2. Всё версионируется: автор, время, причина, diff. Ничего не перезаписывается без следа.
3. Точечный откат: документ, версия, правки автора за период, ошибочная пачка.
4. Память не чёрный ящик: любую правку видно и можно проверить.
5. **В слое памяти нет LLM-вызовов.** Чтение/запись детерминированы.
6. Любой харнесс: MCP, HTTP, CLI.
7. Права по участкам (области, роли, токены, TTL).
8. Конфликты явные: лучше отказ с понятной ошибкой, чем тихая потеря правки.
9. Progressive disclosure: в контекст только нужное; ответы с лимитом и пагинацией.
10. Код рядом с данными (песочница) — вторая волна.
11. Внешние инструменты через реестр — вторая волна.
12. Всё измеряется (место, версии, вызовы, ошибки, кто что сделал).
13. Человек — верховный арбитр; агент предлагает, человек утверждает.
14. Дешёвое хранение: дедупликация, сжатие, квоты.
15. Открытый формат: экспорт в Markdown/JSON.

## 2. Роли
owner/admin, human, agent (имя, токен, права, след в аудите), system, auditor (только чтение журналов).

## 3. Блоки (MVP отмечен [M], 2-я волна [W2], 3-я [W3])
### 3.1 Хранилище [M]
Путь, содержимое, frontmatter (тип, статус, владелец, теги, срок проверки), автор, время, причина, версия, soft delete. Атомарная запись. Лимит размера документа. Импорт/экспорт файлом.
### 3.2 Версии и конфликты [M]
Каждая запись — новая версия (номер, родитель, sha256, автор, причина, размер). Запись по `base_version`/`expected_checksum`; при расхождении отказ, в ответе текущая версия, diff, пересечённые разделы. Трёхсторонняя склейка по разделам (заголовки): разные разделы клеятся, один — конфликт. Откат: версия, автор за период, пачка. История с blame по разделам. Черновики/предложения [W2].
### 3.3 Доступ [M]
Права читать/писать/админ по префиксу пути. Нельзя писать в `owner/`, `rules/`, `README` не-владельцу. Токены на агента: scoped, TTL, отзыв. `owner/inbox` — куда любой агент кладёт предложение. Сканирование секретов/PII при записи: запись с ключом отклоняется. Чистка секретов в логах.
### 3.4 Поиск и навигация [M/W2]
README и карта памяти. ls/tree, оглавление с размерами разделов. Чтение по разделу, диапазону строк, бюджету токенов. FTS5/BM25 с фильтрами (путь, тип, автор, дата). Ссылки и обратные ссылки. Лента «что изменилось с моего прошлого визита». Поиск по истории. Семантика [W2, опционально].
### 3.5 Интерфейсы [M]
MCP (stdio), CLI, HTTP JSON API; веб-UI (дерево, diff, история, откат, права, аудит) [W2]. Единая авторизация.
### 3.6 Progressive disclosure [M]
Маленький стартовый набор инструментов, справка `help <tool>`, понятные ошибки (что не так, что передать), лимиты ответа, пагинация.
### 3.7 Песочница скриптов [W2]: лимиты CPU/RAM/времени/вывода, сеть выключена, секреты не видны, аудит.
### 3.8 Реестр инструментов [W2]: имя, схема, права, лимиты, аудит, секреты в хранилище.
### 3.9 Координация роя [M-lite/W2]
Presence, inbox, «кто менял путь», бриф для нового агента. Доска задач (claim, ревью, приёмка, handoff) была и убрана 12.11.2026 по решению владельца: ориентир для агентов — заметки в памяти (`projects/autoexpertrs/backlog.md`).
### 3.10 Качество знаний [W2/W3]: схемы типов, битые ссылки, дубли, противоречия, статусы (черновик/на проверке/утверждено/устарело), владелец и дата проверки, привязка к коду (drift).
### 3.11 Аудит [M]
Журнал всех действий (чтение, запись, удаление, откат, вызов): кто, что, когда, зачем, из какой сессии/модели. Метрики (документы, версии, размер, топ авторов, ошибки). Экспорт журнала.
### 3.12 Экономика хранения [M]
Метаданные версий в БД, содержимое в блобах по хешу (дедуп), сжатие, дельты [W2], квоты на область/агента/день, лимит версий, GC неиспользуемых блобов, понятный отказ при переполнении. Цель: 1M версий на скромном сервере — единицы-десятки ГБ; проверить нагрузочным тестом.

## 4. Защита от хитростей агентов
Разделять «предложение» и «утверждённое знание». Требовать доказательства (ссылка на прогон/файл/тест/версию данных). Агентам запрещено менять правила и утверждённые документы без владельца. Аномалии: всплеск версий, массовые правки. Ревью человеком для критичных областей.

## 5. Анти-цели
Не харнесс, не LLM-чат, не «умная» память без следа, не векторная свалка, не git с ручными merge для агентов, не общий диск без прав, не падать от роста данных.

## 6. Решения по умолчанию (приняты, можно менять)
Один экземпляр (single-tenant), self-hosted. Git не транспорт, только API (экспорт в git возможен). SQLite (WAL) + блобы по хешу. Python 3.14, uv, stdlib + минимум зависимостей. Доски задач в мозге нет (убрана 12.11.2026). Утверждает человек в критичных областях (`rules/`, `owner/`, `approved/`).

## 7. Метрики успеха
Новый агент выходит на работу за минуты; конфликты и потерянные правки ≈ 0; время точечного отката; стоимость хранения 1M версий; доля устаревших знаний; число инцидентов с секретами.
