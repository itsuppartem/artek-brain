# BRAIN-5: хранение дельтами и экономика места

## Что сделано
- `deltas.py`: построчные дельты (difflib/opcodes, детерминированный JSON), полный снимок каждые K=20 (настраивается `Store(snapshot_every=...)`), глубина цепочки не больше K, дедуп по sha256 сохраняется.
- `Store` пишет версии через `DeltaStorage`; read/diff/blame/rollback/export/gc прозрачны, старые полные блобы читаются без миграции.
- `store.repack()` / `brain repack`: идемпотентно, атомарно по метаданным, после каждой версии проверяет sha256; второй прогон ничего не переписывает.
- `gc()` учитывает базовые блобы цепочек; `archive_old_versions(older_than, keep_last)` сжимает lzma, помечает archived, сохраняет последние N и аудит.
- `disk_report()`: БД/блобы, байты на версию, рост за N дней, прогноз и % квоты; `Quota(max_disk_bytes=...)` отклоняет запись `QuotaError`, чтение продолжает работать.
- CLI: `brain repack [--snapshot-every N]`, `brain disk-report`; repack только для owner. Тесты: `tests/test_deltas.py` (снимки, прозрачность, repack/legacy, GC, архив, квоты, порча дельты, дедуп), CLI repack, нагрузочные под маркером `load`.

## Как проверить
- `uv run pytest -q` — 168 passed, 2 deselected.
- `uv run pytest -m load -q -s` — нагрузка в одном процессе; по умолчанию 20 000 версий, 100 000 через `BRAIN_LOAD_VERSIONS=100000`.
- `uv run brain --root /tmp/b5 init`, записать версии, затем `uv run brain --root /tmp/b5 --token <owner> repack`.

## Что не сделано
- Нет фонового/периодического GC, авто-архивации и квот по областям/агентам: запуск вручную, лимит диска глобальный.
- LZMA на крошечных блобах может дать небольшой прирост; нагрузочный прогон на 100k не выполнялся (только 20k по умолчанию).
