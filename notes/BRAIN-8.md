# BRAIN-8: защита от хитростей агентов

## Что сделано
- `proposals.py`: предложение пишется только в `proposals/<agent>/...`; утверждает owner/human,
  автор не может утвердить сам; правка `approved/` возможна только через новое утверждение.
- `evidence.py` + `tasks.py`: типы `doc_version`, `test_run`, `file_hash`, `audit_ref`; проверка
  заявленного по аудиту; свободный текст не принимается для критичной области; mismatch виден
  в задаче и в очереди ревью (`evidence_mismatch`).
- `runs.py`: серверный запуск в копии каталога, таймаут, seeds, `BRAIN_SEED`, обрезка вывода,
  `hidden/` подмешивается как `_hidden` и наружу отдаётся только pass/fail; статус fail при
  провале hidden даже с зелёными публичными тестами.
- `anomaly.py`: всплеск версий, массовые правки, повторные откаты, перебор защищённых путей,
  чтение hidden, резкий рост размера; инциденты в `owner/inbox/incidents`, `auto_suspend`.
- Права: `rules/`, `scoring/`, `hidden/`, `approved/`, `owner/` не меняются агентами; проверены
  пути с `..`, другим регистром, юникод-двойниками, двойными слешами, `\` и ведущим `/`.
- CLI: `proposal list|approve|reject`, `run`, `anomaly scan|list`, `token suspend|resume`;
  команда прогона берётся из блока `runs` в `settings.json`, агент не может её подменить.

## Как проверить
- `uv run pytest -q` — 158 тестов зелёные.
- `tests/test_defense.py`, `tests/test_cli_defense.py` покрывают каждый вектор и отказы.

## Что не сделано
- Нет HTTP-эндпоинтов для предложений, прогонов и аномалий; нет веб-UI инцидентов.
- Симлинки в рабочем каталоге не проверяются отдельно: защита идёт по логическим путям Store.
